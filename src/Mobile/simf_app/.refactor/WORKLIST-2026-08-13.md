## Rules that condemn correct code

CQP-001 section 5.7 records five rules that had to be narrowed during the
convention programme, on the grounds that "a gate that flags correct code is a
gate that gets switched off". The mechanical pass found two more, both in
`very_good_analysis` rather than in the SIMF checker.

### `specify_nonobvious_property_types` on a Riverpod provider (27 sites)

`dart fix` satisfies the rule by writing Riverpod's internal type name, which
spells the type twice on one line and pushes 16 of the 27 past 80 columns:

```dart
final AutoDisposeFutureProviderFamily<ArchiveEditionDetail?, String>
    archiveEditionDetailProvider = FutureProvider.autoDispose
        .family<ArchiveEditionDetail?, String>((ref, id) async { … });
```

`AutoDisposeFutureProviderFamily` is an implementation type nobody writes by
hand, and the type it names is already spelled on the right-hand side. The
annotations were applied and then reverted; the findings stay open. The fix is
to exclude provider declarations from the rule, not to annotate them, and that
is an `analysis_options.yaml` change for the Phase E gate rather than a code
change. Do not re-run `dart fix` for this code without reverting it again.

### `use_decorated_box` is NOT behaviour-preserving here — never auto-apply it

`dart fix --code=use_decorated_box` rewrites
`Container(decoration: …, child: …)` to `DecoratedBox`. The two are equivalent
only when the decoration has **no border**.

`Container.build` insets its child by `_paddingIncludingDecoration`, and
`BoxDecoration.padding` returns `border?.dimensions`. So with a border,
`Container` insets the child by the border width and `DecoratedBox` paints the
border over the child's edge instead.

Both conversions the pass made were on decorations carrying
`border: Border.all(...)`, and both were reverted:

* `contacts/share_my_contact_screen.dart` — caught by its golden, a 2.42% /
  7366px diff (the QR shifted by the 1px border inset).
* `requests/widgets/request_card.dart` — **no golden covers it**, so the same
  regression would have shipped silently. Reverted on the strength of the
  first, not on evidence of its own.

If this rule is ever applied deliberately, do it only where the decoration has
no border, and only with a golden over the widget.

### `prefer_constructors_over_static_methods` on `AppL10n.of` (1 site)

`static AppL10n of(BuildContext context)` is the Flutter lookup idiom, the same
shape as `Theme.of` and `MediaQuery.of`. A `factory AppL10n.of` would satisfy
the rule and be wrong to read. Left as a static, deliberately.
