# SIMF.E2E.Tests — the browser element sweep (QA programme WS4)

Runs `tools/qa/element-sweep.js` against a live Control Panel with Playwright,
unattended. It is the CI half of the QA programme's element layer; the Chrome
DevTools MCP pass drives **the same file** interactively for exploration.

## Why this exists

The MCP pass cannot gate a commit — it needs an agent in the loop, so nothing
checks a page between one person deciding to look and the next. `/admin/companies`
stayed marked "✅ Real" in `PAGE-INDEX.md` for eight weeks after `a05ef82d`
deleted the page, with a 16-scenario catalogue still describing it. The check
that catches that class of drift is cheap; having something run it is the hard
part.

## Why Playwright for .NET, not Node

This repo has no JavaScript toolchain outside Flutter — no root `package.json` —
and `azure-pipelines.yml` is entirely `DotNetCoreCLI@2` tasks. As a .NET project
this rides the existing `dotnet test` step; a Node runner would be a second
toolchain to install, pin and maintain for one purpose.

## Deliberately narrow

It does **not** re-implement the 2858 hand-authored catalogue scenarios. Those
are prose about intent and would rot the moment a page changed. It runs only what
is **derived from source**, and therefore stays true as the CP evolves:

| What | Catalogue id |
|---|---|
| Every control present, accessibly named, correctly gated at zero selection | `E2E-{NS}-ELS-001` |
| No dead control, no broken image, every same-origin link/asset < 400, no console error, no horizontal overflow | `E2E-{NS}-ELS-002` |
| The page opens for a permitted admin and does not bounce to `/login` | per-page auth gate |

The expected side comes from `docs/tests/element-sweeps/predicted-inventory.json`,
generated by `tools/qa/predicted_inventory.py` from the `SimfDataGrid` callbacks
each page wires. Without it the sweep is presence-only: a page whose Delete
button vanished still sweeps clean, because a control that is not there cannot be
unnamed or broken.

## Running it

With no QA stack reachable every test reports **Skipped** in about two seconds —
not passed, and not failed. A missing stack must not redden `dotnet test` for
someone working on unit tests, and a green test that did nothing is the exact
failure mode this programme exists to remove.

```bash
# once, to fetch the browser
dotnet build tests/SIMF.E2E.Tests -c Release
pwsh tests/SIMF.E2E.Tests/bin/Release/net10.0/playwright.ps1 install chromium

# point it at a stack (defaults are the QA recipe's ports)
export SIMF_QA_CP_URL=http://localhost:5278
export SIMF_QA_WEB_URL=http://localhost:5280
export SIMF_QA_API_URL=http://localhost:5275
export SIMF_QA_ADMIN_EMAIL=...        # never committed
export SIMF_QA_ADMIN_PASSWORD=...
export SIMF_QA_ADMIN_TOTP_SECRET=...

dotnet test tests/SIMF.E2E.Tests -c Release
```

Sign-in goes through the real form and the real TOTP step (`Totp.cs`, RFC 6238 —
the same algorithm as the `Get-Totp` helper). No token is injected into storage:
a shortcut there would skip the redirect and session behaviour the auth-gate
scenarios depend on, and would keep passing after sign-in broke.

**Never put a credential in this repo.** All three come from the environment.

## Regenerating the prediction

```bash
python tools/qa/predicted_inventory.py --json docs/tests/element-sweeps/predicted-inventory.json
```

39 CP pages are bespoke (no `SimfDataGrid`) and carry `predicted: null`. They are
still swept; only the inventory diff is skipped. The generator lists them so the
gap stays visible rather than silently uncovered.
