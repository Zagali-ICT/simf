## Scenarios

### E2E-MOB034-001 — Picker + banner + tabs

```gherkin
Feature: AI session summary
  As a guest
  I want a chosen session's AI summary organised into tabs
  So that I can read the key points, recommendations or speakers

Scenario: The screen renders the picker, the AI banner and the key-points tab
  Given the programme list returns sessions and session "s1" has a published summary
  When /ai-summary?sessionId=s1 opens
  Then the "Choose the session" picker and the "Auto-generated summary" banner are shown
  And the three tabs (Speakers / Key points / Recommendations) and the action row
       (Full text / Share / Save) are shown
  And the active key-points tab shows its bullets; the other tabs' content is hidden
```

**Evidence:** screen test `renders the picker, AI banner and the key-points tab`.

### E2E-MOB034-002 / 003 / 004 — Tab switching + auto-select

```gherkin
Scenario: Switching tabs swaps the content
  When the user taps the "Recommendations" tab
  Then the recommendation text is shown and the key points are hidden
  When the user taps the "Speakers" tab
  Then the speakers are shown

Scenario: No sessionId auto-selects the first session
  Given /ai-summary opens with no sessionId and the programme has sessions
  Then the first session is selected and its summary is fetched (banner shown)
```

**Evidence:** screen tests `switching to the Recommendations tab shows its content`,
`switching to the Speakers tab shows the speakers`,
`with no sessionId it auto-selects the first session`.

### E2E-MOB034-005 / 006 — Not-found + error

```gherkin
Scenario: A 404 shows the no-published-summary state
  Given the selected session has no published summary
  Then "No published summary yet." is shown and the picker still renders

Scenario: A non-404 failure offers retry
  Given the summary read fails with 500
  Then "Could not load the summary." + a Retry button are shown
  When the user taps Retry
  Then the summary is re-fetched
```

**Evidence:** screen tests `a 404 shows the no-published-summary state`,
`a non-404 failure shows error + retry, which re-fetches`.
