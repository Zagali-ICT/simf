# E2E test catalogue — `AI session summary` (`ai-summary`)

> **Authority:** SIMF E2E test catalogue template (D-133). Mobile catalogue — the
> summary read is anonymous (`GET /app/programme/sessions/{id}/summary`); the
> session picker reuses the programme list (`GET /app/programme/sessions`).
> **Re-skinned to KSA Figma frame `1078:14952` (D-465): the المتحدثون / أبرز النقاط
> / التوصيات tabs are replaced by three stacked cards** (key points + recommendations
> as bullet cards; speakers as a "·"-joined line), over the
> **النص الكامل / مشاركة / حفظ** action row, with the **"اختر الجلسة" picker** and
> the **"generated by AI" banner** unchanged. Opened with an optional `sessionId`
> (preselected); otherwise the first programme session is auto-selected. Tested in
> `src/Mobile/simf_app/test/features/ai_summary/session_summary_screen_test.dart`
> with model coverage in `session_summary_models_test.dart`.
>
> **Item #35 (2026-07-20) — TWO videos on the summary surface.** The published
> summary now also carries `recordingUrl` (the session's FULL live recording,
> sourced server-side from `Session.LiveStreamUrl`) and `summaryVideoUrl` (the
> team's OPTIONAL short summary cut, the new `SessionSummary.SummaryVideoUrl`).
> The screen renders each as a labeled player above the tabs (reusing the live
> feature's `LiveVideoPlayer`): "التسجيل الكامل" / "Full recording" and
> "ملخص الجلسة (فيديو)" / "Session summary (video)". Each player is hidden when its
> URL is null, so a summary with neither is byte-identical to the old render.

## Scenarios

```gherkin
Feature: AI session summary (Figma 1078:14952)
  As a guest
  I want a chosen session's AI summary as stacked cards
  So that I can read the key points, recommendations and speakers together

Scenario: The screen renders the picker, the AI banner and the stacked cards
  Given the programme list returns sessions and session "s1" has a published summary
  When /ai-summary?sessionId=s1 opens
  Then the "Choose the session" picker and the "Auto-generated summary" banner are shown
  And the three headings (Key points / Recommendations / Speakers) each show as a card
  And all three sections' content is visible at once (no tab gating)
  And the speakers show as one "·"-joined line
  And the action row (Full text / Share / Save) is shown

Scenario: No sessionId auto-selects the first session
  Given /ai-summary opens with no sessionId and the programme has sessions
  Then the first session is selected and its summary is fetched (banner shown)

Scenario: A 404 shows the no-published-summary state
  Given the selected session has no published summary
  Then "No published summary yet." is shown and the picker still renders

Scenario: A non-404 failure offers retry
  Given the summary read fails with 500
  Then "Could not load the summary." + a Retry button are shown
  When the user taps Retry
  Then the summary is re-fetched

Scenario: Item #35 - both videos render as two labeled players
  Given the published summary carries recordingUrl and summaryVideoUrl
  When /ai-summary?sessionId=s1 opens
  Then a "التسجيل الكامل" / "Full recording" player is shown above the tabs
  And a "ملخص الجلسة (فيديو)" / "Session summary (video)" player is shown below it
  And each player binds its own feed url

Scenario: Item #35 - only the full recording is present
  Given the published summary carries recordingUrl but no summaryVideoUrl
  Then only the "التسجيل الكامل" / "Full recording" player is shown
  And the "Session summary (video)" label is absent

Scenario: Item #35 - only the team summary video is present
  Given the published summary carries summaryVideoUrl but no recordingUrl
  Then only the "ملخص الجلسة (فيديو)" / "Session summary (video)" player is shown
  And the "Full recording" label is absent

Scenario: Item #35 - no videos leaves the layout unchanged
  Given the published summary carries neither recordingUrl nor summaryVideoUrl
  Then no video player and neither video label are shown
  And the tabs sit directly under the session info card as before

Scenario: Item #27 - watching a long recording does not time the session out
  Given a signed-in viewer opens a summary whose recordingUrl is a long video
  And they watch it for several minutes without touching the screen
  Then the shared LiveVideoPlayer pings a 60-second keep-alive on the session clock
  And the SessionGuard treats them as active and silently refreshes the token
  And no idle "stay signed in / sign out" timeout overlay appears
  But the server's 24-hour absolute session cap (D-443) still applies
  When the viewer leaves the summary screen
  Then the keep-alive timer is cancelled (dispose)
```

> **Item #27 (2026-07-22) — keep-alive moved into the shared player.** The
> summary recording / summary-video players use the live feature's
> `LiveVideoPlayer` **directly** (via `SummaryVideoCard`), bypassing
> `LivePlayerSurface`. The watch keep-alive that suppresses the idle
> `SessionGuard` timeout now lives INSIDE `LiveVideoPlayer` itself (was on
> `LivePlayerSurface`), so a long video on THIS surface is kept alive too. See
> the live catalogue E2E-MOB025-024 for the guard behaviour.

**Evidence:** screen tests (5, incl. the no-video-players case) + model tests
(bilingual fallback, line splitting, and the two video-url decodes). The
video-present renders (007-009) are driven on-device against the live player.
The Item #27 keep-alive (011) is unit-tested on the shared player
(`live_video_player_test.dart` — mount marks, 60s tick re-marks, dispose
cancels); the true multi-minute watch is a device check.
