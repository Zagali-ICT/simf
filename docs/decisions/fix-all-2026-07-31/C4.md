# C4 — `FR-903` — "session started but you have not attended" reminder

## DECISIONS_LOG

### D-NEXT — FR-903 not-attended reminder, deduplicated by notification rather than a stamp column

**Context.** The booking half of FR-903 shipped (`BookingConfirmed = 40`,
`SessionReminder = 41`, `BookingReleased = 51`). The not-attended half never did:
`NotificationKind` had no such value across 0-58, and
`ReservationNoShowReleaseWorker` — the only worker reasoning about no-shows — calls
`ISeatReservationService.ReleaseNoShowsAsync` to free the seat and notifies nobody.
Owner answer **Q8**: build to the stated requirement.

**Decision.** `NotificationKind.SessionNotAttended = 59` (additive, persisted by name,
so no schema or wire change under the frozen-enum rule — added by the Prep agent) plus
`SessionNotAttendedReminderWorker`, a sibling of `SessionReminderWorker` that fires at
Start + grace to holders of an active reservation with no `HallAttendance` row.

**The load-bearing decision: no additive column.** The task permitted mirroring
D-217's `Session.ReminderSent` as a once-only stamp. It was not taken, and the reason
matters:

- D-217's reminder is once **per session**, so a per-session stamp is the right key.
- This one is once per **(attendee, session)** — two holders of the same session must
  both be nudged, so a per-session stamp cannot express it. A per-attendee stamp would
  need a whole new table.
- `NotificationRequest.DeduplicateByRelatedEntity` (D-713) already gives exactly
  one-per-(user, kind, entity). Using it makes the scan **idempotent by construction**:
  no claim-then-dispatch dance, no crash window, a restart mid-sweep re-runs
  harmlessly, and the shipped mobile wire contract is untouched.

Cost: the sweep re-scans a due session each tick. That is bounded by a
`ReminderWindow` of 20 minutes after a 10-minute `ArrivalGrace`, so a session is
scanned at most ~20 times and only while it is still running.

**Other rules encoded.**

- A session whose `End` has passed is skipped — nudging someone to attend a finished
  session is noise, not a reminder.
- The anti-join tests for **any** `HallAttendance` row, open or closed: someone who
  arrived and left did attend.
- A released reservation is excluded, so the nudge cannot arrive after
  `ReservationNoShowReleaseWorker` has already freed the seat.
- One attendee's dispatch failure is logged and skipped, never aborting the batch —
  the containment `SessionReminderWorker` already uses.
