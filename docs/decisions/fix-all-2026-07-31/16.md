## DECISIONS_LOG

### D-NEXT — #16: the raw-colour sweep is complete and now ratcheted; the shared app/widgets layer is tokenised

**The register's evidence was stale.** It listed 40 remaining `Colors.white` —
including 11 in `simf_page_shell.dart` and four named feature files. Re-measured
on `qa/programme-ws0` on 2026-07-30: **zero**. A repo-wide grep for `Color(0x` /
`Colors.<name>` under `lib/` returns matches in `lib/app/theme/tokens.dart`
**only**. The colour half of the sweep had already landed; the register was
written against an older tree. Recorded so the next reader does not re-open a
closed item.

**What was actually left** was the second half of the rule — *no inline
`TextStyle`* — in the layer owner decision **Q11** put in scope (the shared
`app/widgets` layer). Swept, each replacement byte-identical:

| Site | Before | After |
|---|---|---|
| `more_drawer.dart` — drawer heading | `TextStyle(surface, textXl, w600)` | new `SimfTokens.labelWhiteSemiboldXl` (same three values) |
| `more_drawer.dart` — `_DrawerTile` title | `TextStyle(color: surface)` | **removed** — the theme's `listTileTheme.textColor` is already `SimfTokens.surface`, so the override restated the token it duplicated |
| `more_list.dart` — `MoreRow` title | `TextStyle(surface, textMd, w500)` | existing `SimfTokens.labelWhiteMedium` (identical) |
| `accessibility_font_size_card.dart` — chip label | ternary inside one `TextStyle` | `selected ? labelWhiteSemiboldSm : labelBeigeSm` (identical: the explicit `w400` matched the inherited `bodyMedium` weight) |

`simf_page_shell.dart` and both shared dialogs (`simf_confirm_dialog`,
`simf_info_dialog`) were already clean — verified, not assumed.

**Ratchet, not a checklist.** `test/repo/design_token_ratchet_test.dart` asserts
(a) no raw colour anywhere under `lib/` outside `tokens.dart`, and (b) zero
inline `TextStyle(` in the swept files, listed explicitly. (b) fails on the
pre-fix tree. The swept list is append-only: entries are added as the sweep
reaches more files and are never removed. A prose checklist is what let this
drift for months; a test cannot.

**Deliberately NOT swept this round:** ~117 inline `TextStyle` sites remain
across the feature screens and ten further `app/widgets` files
(`qr_scan_view`, `simf_bottom_nav`, `simf_form_scaffold`, `simf_identity_cell`,
`simf_language_toggle`, `simf_scanner_body`, `simf_scanner_frame`,
`simf_search_field`, `simf_states`, `simf_tiles`). They are token-composed
already (a few carry raw font sizes: 24, 12, 10) but each needs a new named
token, and several are rendered by goldens that this run cannot re-lock. Sweeping
them blind would ship pixel regressions to close a low-severity cosmetic item.
They belong in a follow-up that can run `--update-goldens`, and the ratchet's
swept list is where they get added one at a time.
