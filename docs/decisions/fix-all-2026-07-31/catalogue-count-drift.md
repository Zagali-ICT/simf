## DECISIONS_LOG

### D-NEXT — the E2E catalogue size is generated, never hand-copied into prose

The Round-1 charter (`docs/tests/SIMF-Production-Readiness-Round1.md`) opened with
"a **164-file / 2,142-scenario** per-page Gherkin E2E catalogue" and repeated
"2,142" in §5. Re-derived on 2026-07-30 the catalogue held **183 pages** (94
Control Panel + 69 mobile + 19 Website + 1 other) and **2,884 Coverage-matrix
scenarios**, matching the roll-up in `docs/tests/e2e/README.md`. A tester scoping
a round from the charter would have under-scoped it by roughly 700 scenarios — a
third of the round.

**Decision: re-deriving the number is not the fix.** While this very correction
was being written the scenario count moved again (2884 → 2887) as another agent
in the same run appended to an existing catalogue file. Any figure typed into a
paragraph is stale before the paragraph is committed. So the charter
now states **no** catalogue size at all — it names the two generated sources and
says to read the number from them — and the generator emits the size itself. Two
changes:

1. **`tools/testbook/build_testbook.py` now emits the size on every run**, in
   three places:
   - **stdout** — a `CATALOGUE SIZE` block after the per-sheet totals;
   - **the workbook, sheet `00 · How to use`** — a dated provenance line under the
     "generated by" line;
   - **the workbook, sheet `01 · Summary`** — a "Catalogue size" block under the
     roll-up totals (pages, the per-surface split, scenarios, and the source).

   It also parses the `**Pages catalogued:**` / `**Total scenarios:**` roll-up out
   of `docs/tests/e2e/README.md` and prints a **MISMATCH** warning naming the
   README and the build gate when the two disagree. The warning is **not fatal**
   on purpose: the workbook has to keep regenerating so the number *can* be fixed.
   Enforcement stays with the xUnit gate, which does fail the build.

   The new `catalogue_size()` counts **Coverage-matrix rows only**
   (`MATRIX_ROW_RE`), deliberately identical to `E2eCatalogueIntegrityTests
   .MatrixRow`, so the figure the script prints is the figure the build enforces.
   That is narrower than the projector's own `extract_scenarios()`, which stays
   tolerant (it also harvests `### E2E-… — title` headers and inverted tables)
   because a workbook row is worth having even from an unusually authored page.
   The two answer different questions — "how big is the catalogue" vs "how many
   rows did the projector build" — and the code comment says so, so nobody
   "fixes" one to match the other. The per-page loop in `build()` now shares the
   same `catalogue_files()` helper, so the projector and the counter can never
   disagree about which files are catalogue files.

2. **The charter stops carrying a figure at all.** The preamble's "164-file /
   2,142-scenario" clause becomes "a large per-page Gherkin E2E catalogue", and a
   new "Catalogue size — where the number comes from" section names the two
   generated sources (the build-gated README roll-up; re-running the generator),
   notes that both count on the same rule so they are comparable, and keeps the
   stale-by-700 episode as the worked example of why. The old §5 sentence "every
   one of the 2,142 per-page scenarios is present" becomes "**every** per-page
   scenario in the catalogue is present" and points at the workbook's own
   generated figure. The only numbers left in the charter are historical facts
   about the drift itself, which cannot go stale.

`docs/tests/e2e/README.md` was **not** edited: it was already correct at 183 /
2884, and it is a global file the orchestrator merges. `docs/tests/SIMF-Production-
Readiness-TestBook.xlsx` was **not** regenerated in this change — other tracks in
this run are still authoring catalogue files, so a workbook built now would be
stale before the run ends. Regenerate it once, after the run merges; the size line
lands in it automatically at that point.

Verified: the module compiles (`python -m py_compile`) and the new functions were
exercised directly against the live catalogue — first returning `183 pages / 2884
scenarios` with `index roll-up agrees`, then `2887` an hour later with the
MISMATCH warning firing correctly against the unchanged README. Both the happy
path and the warning path are therefore observed, not assumed. `build()` itself
was not run: it would overwrite the workbook mid-run.

**Note for whoever merges this run:** the README roll-up
(`**Total scenarios:**`) is a build gate, and concurrent tracks are still adding
scenarios. It must be recounted once at the end of the run or
`The_index_roll_up_matches_the_catalogue_it_describes` fails. Running
`python tools/testbook/build_testbook.py` prints the correct pair to paste in.
