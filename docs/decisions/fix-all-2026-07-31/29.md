## DECISIONS_LOG

### D-NEXT — #29: a Workshop's app detail is reduced to its title + time block

`SIMF-Bugs-And-Updates-TODO.md` #29 asks that workshop management "show the
workshop title and time only". The CP half is discharged by **reuse** (owner
**Q10**, 2026-07-30): a workshop is an ordinary `Session` row with
`Type = Workshop`, so the existing session admin plus `HallAttendance` already
manage it and no new Control-Panel surface is built. The app half was absent —
grepping the whole sessions feature found `workshop` only in the enum, the
empty-state string and the filter tab, so a workshop rendered the **full**
session detail: description, speakers, the اسأل المحاور card, the seat/join
block, the CTA row and the ملخص الجلسة / رابط الجلسة actions.

**Built:** `SessionDetailBody.build` opens with a guard — when
`detail.type == SessionType.workshop` it returns `_workshopBody()`, a list
carrying only `SessionHeaderCard(titleAndTimeOnly: true)`. The new
`titleAndTimeOnly` flag drops the card's category pill and its two action
buttons, leaving the title + the clock/calendar meta line. Any other type, and a
**null** type from an older API, renders the full detail unchanged — the
reduction is opt-in on an explicit `Workshop`.

**Wire dependency (open, outside this track).** `SessionDetail` now decodes
`type` with the same tolerant `SessionType.fromJson` the list item uses, but
`SIMF.Contracts.Programme.PublicSessionDetail` does **not** yet carry a `Type`
member (`PublicSessionListItem` does — `PublicSessions.cs:42`), so the field is
absent on the wire today and the branch stays inert against a live server. The
backend half is a two-line **append-only** addition — `SessionType? Type = null`
at the end of `PublicSessionDetail` (D-219 append-only, no schema change) plus
`session.Type` in the `ProgrammeSessionService.GetAsync` projection and its
`new PublicSessionDetail(...)` call. That belongs to the API track; recorded here
so it is not lost.

**Not suppressed on purpose:** nothing. "Title and time only" is read literally —
the add-to-calendar / reminder CTAs go too, since neither is a title nor a time.
